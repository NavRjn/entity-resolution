# Findings from first hands-on review (2026-11-04)

Scope: run the app, open a saved run, inspect the UI and API, try the eval script. No LLM calls were made and no API credits were spent. Nothing was changed in the code.

## How it was checked
- API: `uvicorn api.main:app` on :8000 (an instance already running from an earlier session answered; a second start failed to bind the port, harmless). Frontend: Vite on :5173.
- Run inspected: `20261031_134601` (source `uploads\test-synthetic.txt`, docling backend).
- Browser (Playwright, headless): `/runs` and `/runs/20261031_134601` viewed. The `/graph` page was **not** opened in the browser; only the JSON from `/api/runs/<id>/graph` was inspected.
- `test.py --file test --run 20261031_134601` (with `PYTHONUTF8=1`).

## Findings

### F1. There is no valid quality baseline
`test.py` reports 0% entity and relationship F1 for the run above. This is **not a measurement of the pipeline**: `uploads/test-synthetic.txt` no longer exists, and `data/test.gt.json` (49 entities, 34 relationships) describes the Aurora document, while the run extracted Northbridge/Harbor Re/Elena Voss entities. Run and ground truth are for different documents. No F1, latency or cost number for the docling backend exists yet. (The user is preparing infrastructure to produce one.)

### F2. Provenance is missing in docling runs (blocks analyst use)
In `outputs/20261031_134601/output.json`:
- every citation has `start_char: 0`, `end_char: 0` and a placeholder quote such as `#/texts/0`;
- the same three placeholder citations repeat for every entity;
- every graph edge has `evidence: ""`;
- aliases are `[""]` (or a stringified list, e.g. `"[{'id': 'Agreement_833ec...', ...}]"` for the Agreement).
A register without verifiable quotes cannot be trusted by an analyst. This is the top product defect.

### F3. Same entity returned with two types
`/api/runs/<id>/graph` lists `Northbridge Risk Holdings` as `Company` and as `Person`, and `Harbor Re Analytics` likewise (7 nodes, 3 of them duplicates by name). Entity typing and deduplication are not enforced.

### F4. Relationships are thin and unvalidated
7 entities produced edges of type `controls`, `participates_in`, `related_to`; most are the catch-all `related_to`. `validate_relationship` in `run.py` always returns `True` (known issue #7), so nothing is ever rejected.

### F5. UI defects visible immediately
- Run Detail shows **Total Entities 7, Companies 0, Other Entities 0** while listing a Company (entity type casing mismatch, known issue #2).
- The nav bar is plain unstyled text links (`Runs | Uploads | Upload New`) next to otherwise styled cards.
- The Runs list shows status **"unknown"** for the run, and "Total Runs 35".
- Manifest `run_id` is `"0"` while the directory is `20261031_134601`; many run directories have no `manifest.json`/source (list shows `source_file: null`).
- `GET /api/runs/<id>/entities` returns 404 for docling runs; `POST /api/runs/<id>/relationships` returns 405/500 (only wired to the legacy pipeline).
- A full-page screenshot of the run page timed out in the headless browser once; viewport screenshots worked. Not investigated.

### F6. Run failures are invisible
Known issue: a crashed background task leaves the run "pending" forever (no `status.json`). In a demo this looks like a hang.

### F7. Evaluation tooling is incomplete
- `test.py` crashes on Windows consoles with `UnicodeEncodeError` when printing box-drawing characters unless `PYTHONUTF8=1` is set.
- Ground truth: one real-sized set (`test.gt.json`) and three 5-entity toy sets. No German, no alias GT, no multi-document GT.
- The metrics reported are entity and relationship precision/recall/F1 and per-chunk TP/FP; no alias/cluster metric, no citation-validity metric, no latency or cost.

### F8. Operational notes
- Docling engine hard-codes OpenAI `gpt-4o`; the provider config in `config.yaml` only affects the legacy pipeline (matters for on-prem, see `deployment-options.md`).
- `GET /debug` is unauthenticated.
- The repo relies on a sibling checkout `../docling-graph` for `uv sync`.
- Data folders are relative to the working directory.

## Cross-reference
Items F2, F3, F5 (casing), F6 and F4 map to already-pinned or documented issues in `docs/tests/known-issues.md` (#1, #2, #7 and "failed runs look pending"). F2 (placeholder citations), F3 (duplicate typed entities) and the empty `evidence` are **not** in that list and should be added to the roadmap's week 1-2 work.

## Not verified

- Behaviour of the graph page in the browser, the upload-and-run flow, and German text.
- Latency and cost of a run.
